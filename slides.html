The Problem Statement

Why Campus Facilities Need "BookIt"

Replacing manual logbooks and chaotic WhatsApp permission chains.

❌ The Old Manual Way

Students and professors physically hunt for keys, sign paper registers, and face double-booked classrooms on the day of major presentations or events.

⚠ Scheduling Clashes

No centralized view to verify whether NC 27 or NC 28 is occupied at 10 AM, causing embarrassing collisions between departments.

✔ The BookIt Solution

Instant date-based availability checks, departmental grouping (CSE, Electrical, Mech), capacity filtering, and pre-drafted formal requisition emails to HODs.

Focus: Zero scheduling confusion, verified student & faculty identities.

Senior Developer Insights

Bugs Explained & Architecturally Prevented

Techniques used to make this frontend robust and production-grade.

🐛 Form Default Reload Bug

Problem: Standard HTML form submissions cause a full page refresh, wiping state.
Fix: Handled via e.preventDefault() with client-side async submission.

🐛 Timezone Date Offset Bug

Problem: Calling new Date().toISOString() produces UTC date which shifts yesterday in Indian Standard Time (UTC+5:30).
Fix: Formatted local date string helper avoiding timezone shift.

🐛 Clash Detection Bug

Problem: Two users trying to book NC 27 for the same date.
Fix: Client and API clash validation checking active records before saving.

Clean defensive programming prevents 99% of frontend support tickets.

Backend API Integration Blueprint

Ready for seamless connection with Bhargav's REST backend.

Centralized API Layer

All HTTP and mock communication is isolated in js/api.js.
To plug into real backend: change USE_MOCK = false and configure BASE_URL.

Standard REST Endpoints

• POST /api/auth/register
• POST /api/auth/login
• GET /api/venues/search?date=...
• POST /api/bookings

Session Security

Equipped with token storage, protected route checking (isAuthenticated()), and auto-logout on token expiration.

Zero frontend refactoring needed when the backend goes live!
